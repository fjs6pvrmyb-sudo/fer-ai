## Verificación local y decisión

Pasaron `npm ci`, TypeScript, lint, build y la auditoría de dependencias de producción, que reportó cero vulnerabilidades. En una instancia Supabase desechable se aplicaron ocho migraciones. Pasaron 61 pruebas unitarias, 27 integraciones de Auth, RLS y Core, cinco integraciones fiscales, tres comprobaciones SQL de reversión y 17 recorridos Playwright. Se usaron únicamente datos ficticios y proveedor demo, deshabilitado o controlado en pruebas.

**NO GO para el PR #2 publicado.** El commit remoto todavía carece de las correcciones de esta rama. Revisarlas y verificar CI alojado para el SHA que se vaya a integrar. La protección efectiva frente al abuso del login es un requisito adicional para abrir la preview.

## Antes de Vercel

Usar protección de preview y datos de prueba separados. Comprobar TLS y cabeceras en respuestas de login, redirecciones y rutas autenticadas. Mantener claves privilegiadas y de IA fuera de `NEXT_PUBLIC_*`, usar un scope de secretos por ambiente y verificar `auth.sessions` en el Supabase alojado antes de aplicar la migración. Configurar registro cerrado, MFA administrativa, protección contra abuso y alertas. Empezar con el proveedor demo o deshabilitado y CSP de scripts en observación. El despliegue, las llamadas de IA pagadas y cualquier uso de Hacienda requieren autorización por separado.
